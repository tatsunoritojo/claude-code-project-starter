# 実装前リサーチ（search-first）

コードを書く前に「もう存在しないか」を必ず確認する。Claude が即座に自作実装へ走るのを止める。特に既存プロジェクト改修では、既存実装の見落としによる重複実装を防ぐ。

## 起動条件

- 新機能の実装に入る直前
- 依存ライブラリ・外部連携を追加しようとするとき
- ユーティリティ・ヘルパー・抽象を新規に書こうとするとき
- ユーザーが「X の機能を追加して」と言い、コードを書き始めそうなとき

## 鉄則

1. **書く前に探す。** 探さずに実装へ進まない。
2. **ローカル既存コードを最優先で見る。** repo 内の既存設計・既存関数・既存テストは、実装上の一次資料として扱う。同じ処理が既にあれば再利用・拡張する。
3. **一次資料優先。** 外部仕様・挙動は公式ドキュメント/一次資料で確認し、記憶や推測で断定しない。引用は出典（URL または `path/to/file.py:行`）を併記する。
4. **調査できなかったら「調査不能」と明記する。** チャネルが使えなかった/結果が出なかった場合に「なし」「存在しない」と書かない。「このチャネルは調査できなかった」と正直に書く。

## 4つの確認チャネル

実装文脈では、まずプロジェクト内を見てから外へ出る。

| # | チャネル | 確認方法 | 使えない時 |
|---|---|---|---|
| 1 | ローカル既存コード | Glob でファイル特定 → Grep で既存設計・関数・テストを確認（bash の grep/find/cat は使わない。複数は並列 Read） | 「可視範囲のみ確認」と明記 |
| 2 | 一次情報 | 公式ドキュメント・API 仕様・一次資料 | 推測で埋めず「一次資料未確認」と明記 |
| 3 | 既存ライブラリ | npm / PyPI 等。保守状況・ライセンス・依存を見る | registry 未確認なら網羅を主張しない |
| 4 | MCP / ツール | 利用可能ツール一覧・MCP 設定を確認 | 「MCP 未確認」と明記 |

3クエリ以上にわたる広い探索は、Explore / general-purpose サブエージェントに委譲してメイン文脈を節約する。

## Quick Mode（軽い作業・インライン）

着手前に頭の中で:

0. これは repo に既にあるか？ → Glob/Grep で関連モジュール・テストを先に確認
1. よくある問題か？ → npm/PyPI を探す
2. 一次資料で挙動を確認したか？ → 公式ドキュメント
3. MCP / 既存ツールで賄えないか？

## Full Mode（非自明な機能・サブエージェント委譲）

```
Agent(subagent_type="general-purpose", prompt="
  次の機能の既存解を調査: [説明]
  言語/FW: [LANG]  制約: [制約]
  探索: ローカル repo / 公式ドキュメント / npm・PyPI / MCP / GitHub
  返答: 候補の構造化比較 + 推奨（Adopt/Extend/Compose/Build）+ 各出典
")
```

## 判断（Decision Matrix）

判断の前に一言、アクター視点を置く（この機能は誰がどう使うか）。

| シグナル | 判断 |
|---|---|
| 完全一致・保守良好・MIT/Apache 等 | **Adopt** — そのまま導入して使う |
| 部分一致・土台は良い | **Extend** — 導入 + 薄いラッパー |
| 弱い一致が複数 | **Compose** — 小さなパッケージを2〜3組み合わせ |
| 適切なものが無い（必要なチャネルは調査済み） | **Build** — 自作。ただし調査結果に裏打ちされたうえで |

### Build を選ぶ前の確認範囲（作業規模に応じる）

- **非自明な新機能・依存追加・外部連携・設計変更**: 原則として4チャネルすべてを確認する。
- **軽微な修正・既存関数内の局所修正**: ローカル既存コード確認（チャネル1）を最低条件とする。
- いずれの場合も、**調査できなかったチャネルがあれば、その旨を明記**してから Build を選ぶ。

## 自律実行ポリシーとの接続

依存追加は Yellow。導入前に「何を/影響範囲/主要リスク」を1〜3行で示してから実行する。

## アンチパターン

- **即コード**: 存在確認せずユーティリティを書き始める
- **既存実装の見落とし**: repo 内の既存関数・設計を確認せず重複実装する
- **沈黙スキップ**: チャネルが使えなかったのに「見つからなかった」と報告する（→「調査不能」と書く）
- **過剰ラップ**: ライブラリを包みすぎて利点を失う
- **依存肥大**: 小機能のために巨大パッケージを入れる
- **記憶で断定**: 仕様を一次資料で確認せず「〜のはず」で進める
