# Handoff Closeout

セッション終了時の handoff 処理。グローバル CLAUDE.md「セッション終了時の規律」を実行手順に落とし込んだもの。**永続情報の更新が完了するまで「一区切り」「休憩」「次回に引き継げる」と報告しない**。

## 起動条件

### 主トリガ（明示終了シグナル）
- ユーザーが「セッションを終了してよいですか？」と聞く
- ユーザーが「ここで終わる」「休憩」「続きは次回」と示す
- 明示呼び出し（「handoff-closeout で締めて」等）

### 副トリガ（補助条件・単独では起動しない）
- **「コンテキスト残量が少ない」は単独では起動しない**。明示終了シグナル、または非軽微な進捗があるときの補助条件として扱う
- 大きな進捗の節目で、明示シグナル前に能動的に「handoff 残しますか？」と提案してよい

## 発火条件チェック（最初に実行）

グローバル規律の発火条件のいずれかに該当するかを最初に確認する。**該当しなければスキップ**してよい:

- [ ] コードまたは文書を更新した
- [ ] PR / コミット / ブランチ / 設計判断が発生した
- [ ] 次アクションが残っている
- [ ] ユーザーが明示終了シグナルを示した

該当しない場合: 「今回は永続情報の更新は不要と判断します」と報告して終了。

## 実行フロー

### Step 1: 進捗の整理

以下4項目を整理する:
- **今回完了したこと** — 1〜3行
- **次に着手する1件** — 具体的な次アクション
- **次に読むべきファイル / 根拠ファイル** — パスと該当箇所
- **未解決事項** — 「今回の対象外」「次回扱い」を明記

### Step 2: 保存先決定（フォールバック順）

#### 主経路: `<project>/CLAUDE.md`「次セッション着手用」欄

1. プロジェクト直下の `CLAUDE.md` を Read
2. 「次セッション着手用」セクションがあるか確認
3. **あれば** → 該当欄を Edit で更新（最終更新日を含む）
4. **なければ** → ユーザーに以下の提案を出す:
   ```
   このプロジェクトの CLAUDE.md には「次セッション着手用」欄がありません。
   追加すれば次回以降、終了時の保存先がぶれません。追加しますか？
   ```
   - **追加同意** → CLAUDE.md に新規セクションを挿入（位置: プロジェクト概要直下、技術スタックの前を推奨）して内容を埋める
   - **追加見送り** → フォールバック経路へ

#### フォールバック経路: `<project>/docs/notes/yymmdd_handoff.md`

- 「次セッション着手用」欄が無く、追加も見送られた場合のフォールバック
- 命名はグローバル「ドキュメントファイルの命名規則」に従う:
  - 基本: `yymmdd_handoff.md`
  - 衝突時: 内容名を具体化（`yymmdd_handoff_<topic>.md`）→ それでも衝突なら `_2`, `_3` の連番
- ファイル内容は Step 1 の4項目を Markdown で書き下ろす
- `docs/notes/` ディレクトリが無ければ作成

#### アイディア管理の同期（任意・運用している場合のみ）

アイディア管理（プロジェクト配下に `ideas/<id>.json` を置く等）を運用している場合のみ、以下のいずれかに該当するときに同期する:
- セッションがアイディア JSON を起点に始まった
- セッション内でアイディアの status を更新した（`placed`→`in_progress`→`done` 等）

該当する場合、対象 JSON と（インデックスを運用していれば）該当エントリを **両方同期更新** する。アイディア管理を運用していない、または無関係なセッションでは実施しない。

#### 特殊ケース: プロジェクトに紐づかないセッション → `~/.claude/global-handoff.md`

cwd が特定プロジェクトに紐づかないセッション（グローバル設定改修・横断作業など）の場合、専用保存先 `~/.claude/global-handoff.md` を使う:

- 主経路（project CLAUDE.md）もフォールバック（docs/notes/）も自然に当てはまらないため、**専用ファイルに最新1件を保存**する
- **常に追記ではなく上書き運用** — 最新1件のみ保持（古い handoff は新しいもので置換）
- フォーマットは project-local「次セッション着手用」と同じ5項目（現在地 / 次アクション / 参照ファイル / 未解決 / 最終更新）
- 通常のプロジェクト anchored なセッションではこのファイルを使わない（汚染防止）

### Step 3: 書き込み

- 既存「次セッション着手用」欄の更新: Edit で該当部分を置換
- 新規追加: Edit でセクション挿入（プロジェクト概要直下、技術スタックの前）
- handoff 文書: Write で `docs/notes/yymmdd_handoff.md` を作成
- アイディア管理の同期: Edit で該当 JSON / インデックスを更新（運用している場合のみ）

### Step 4: 報告

```
■ Handoff 残しました

保存先: <パス>
今回完了: <1〜2行>
次に着手: <1件>
参照ファイル: <パス>
未解決 / 別扱い: <あれば>

次セッションは X から再開できます。
```

## 「次セッション着手用」欄の更新フォーマット

```markdown
## 次セッション着手用
- 現在地: <Step 1「今回完了したこと」>
- 次アクション: <Step 1「次に着手する1件」>
- 参照ファイル: <Step 1「次に読むべきファイル」>
- 未解決 / 別扱い: <Step 1「未解決事項」>
- 最終更新: <YYYY-MM-DD>
```

## 既存スキル/ルールとの関係

- **doc-init**: プロジェクト初期化（初回作成）。既存ファイルへの遡及追記はしない方針。handoff-closeout は終了時に欄が無ければ「追加提案」を行うことで補完する。役割分担はこの分業で完結
- **deploy-check**: デプロイ前検証。別物
- **グローバル「セッション終了時の規律」**: このスキルの根拠

## 重要原則

1. **発火条件チェックを最初にやる** — 該当なしなら起動しない（不要起動の抑制）
2. **既存 CLAUDE.md への追加は必ずユーザー同意を経る** — 黙って追加しない
3. **コンテキスト残量だけで起動しない** — 明示終了シグナル、または非軽微な進捗との組み合わせで判断
4. **永続化が完了するまで「一区切り」と報告しない** — グローバル規律の完了条件を厳守
5. **アイディア管理の同期は任意** — 運用していて、かつアイディア起点 / status 更新時のみ。無関係なセッションでは触らない
6. **保存先がぶれそうな状況ほど明示的にフォールバックを宣言する** — 「欄が無い → 追加提案 → 見送り → docs/notes/ にフォールバック」の流れをユーザーに見せる
