# 戦略的 compact（手動・判断支援）

任意 `/compact` を「論理的な区切り」で打つための判断スキル。自動実行（フック・閾値スクリプト・suggest-compact.js）は使わない。いつ打つかは Claude が下表で判断し、打つ前に必ず文脈を会話内に明示する。

## 起動局面

- 長セッションが文脈上限に近づいた（200K+ トークン目安）
- 多フェーズ作業の節目（調査 → 計画 → 実装 → テスト）
- 同一セッション内で無関係なタスクに切り替えるとき
- マイルストーン完了直後、次の作業に入る前
- 応答が遅く・不安定になり文脈圧が疑われるとき

## compact する / しない（局面別）

| 遷移 | compact? | 理由 |
|---|---|---|
| 調査 → 計画 | する | 調査文脈は嵩張る。計画が蒸留物 |
| 計画 → 実装 | する | 計画は Todo / ファイルにある。コード用に文脈を空ける |
| 実装 → テスト | 場合による | 直近コードを参照するなら残す。焦点が変わるなら compact |
| デバッグ → 次機能 | する | デバッグトレースが次作業を汚染する |
| 実装途中 | しない | 変数名・パス・部分状態を失うと代償が大きい |
| 失敗アプローチの後 | する | 行き止まりの推論を消してから別案へ |

## compact で残る / 消える

| 残る | 消える |
|---|---|
| CLAUDE.md の指示 | 中間推論・分析 |
| Todo リスト | 既に読んだファイル内容 |
| memory ファイル（~/.claude/projects/.../memory/） | 複数ステップの会話文脈 |
| git 状態（コミット・ブランチ） | ツール呼び出し履歴 |
| ディスク上のファイル | 口頭で述べた微妙な好み |

## compact 前の必須手順（消える前に明示）

compact を打つと判断したら、実行前に次の4点を**会話内に明示する**（セッション終了時の規律と同じ項目）。これが原則であり、毎回行う:

1. **作業状態** — 今どこまで完了したか
2. **次アクション** — 次に着手する1件
3. **未解決事項** — 今回対象外の保留も含む
4. **参照ファイル** — 次に読むべき / 根拠となるファイル（path 明示）

明示が済むまで compact を実行しない。

## 永続化を検討する条件（会話内明示に加えて）

compact は同一セッション内で作業を続けるための文脈圧縮であり、永続化は原則不要。
ただし次のいずれかに該当する場合のみ、handoff-closeout または CLAUDE.md「次セッション着手用」欄の更新を検討する:

- 非軽微な設計判断が確定した
- 作業をまたいで後日参照する可能性が高い
- 実装・設計・レビューで明確なマイルストーンが完了した
- compact 後に失われると復元困難な情報がある

永続化する場合は、新しい保存先を定義せず、既存の handoff-closeout / CLAUDE.md 運用に従う。
保存先が不明なときは、会話内に4点を明示するに留める。

## compact ≠ セッション終了

- **compact**: 同一セッション内の文脈圧縮。作業は続く。永続化は原則不要。
- **handoff**: 次セッションへの引き継ぎ。セッションを閉じる。永続化が本務。
両者を混同しない。compact では会話内明示を原則とし、上の条件に当たるときだけ永続化を検討する。

## ベストプラクティス

1. 計画確定後（Todo / ファイル化済み）に compact して仕切り直す
2. デバッグ解決後、続行前にエラー解決文脈を消す
3. 実装途中は compact しない（関連変更の文脈を保つ）
4. compact は提案ではなく判断 — 打つなら理由を1行添える
5. compact 前に重要文脈をファイル / memory に書く（永続化条件に当たる場合）
6. `/compact <要約>` で次の焦点を指定する（例: `/compact 次は auth middleware の実装に集中`）
